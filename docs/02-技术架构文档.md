## 一、整体架构

### 1.1 架构哲学

**本地优先（Local-First）**：数据存在用户设备上，不依赖网络也能完整使用。这是闪卡应用的正确形态——用户随时随地要能复习，不能因为网络差就卡住。

```
┌─────────────────────────────────────────────────────┐
│                   用户设备（浏览器/App）               │
│                                                     │
│   ┌─────────────┐     ┌─────────────────────────┐  │
│   │  React UI   │────▶│     FSRS-5 引擎（TS）    │  │
│   │  (Vite)     │     │  纯函数，无副作用          │  │
│   └──────┬──────┘     └─────────────────────────┘  │
│          │                                          │
│   ┌──────▼──────────────────────────────────────┐  │
│   │            IndexedDB（Dexie.js）             │  │
│   │   Decks | Cards | ReviewLogs | Settings      │  │
│   └──────────────────────────────────────────────┘  │
│                                                     │
│   ┌──────────────────────────────────────────────┐  │
│   │         Service Worker（PWA 离线缓存）         │  │
│   └──────────────────────────────────────────────┘  │
└───────────────────────┬─────────────────────────────┘
                        │ 可选：云端同步
                        ▼
              ┌─────────────────┐
              │  Fastify 后端   │
              │  (Node.js)      │
              │  SQLite         │
              └─────────────────┘
```

### 1.2 V1.0 范围

V1.0 **纯前端**，无后端。所有数据存 IndexedDB，Service Worker 保证离线。

后端是 V2.0 的多设备同步需求，V1.0 不开发。

### 2.2 FSRS-5 算法选型

使用 `ts-fsrs` 库（TypeScript 实现，与 Anki 官方 FSRS-5 实现对齐）。

```bash
pnpm add ts-fsrs
```

核心 API：
```typescript
import { createEmptyCard, fsrs, generatorParameters, Rating } from 'ts-fsrs'

const params = generatorParameters()  // 默认参数
const f = fsrs(params)
const card = createEmptyCard()

// 用户打分后计算新状态
const result = f.repeat(card, new Date())
// result[Rating.Good] → 下次复习时间、新的稳定性等
```

## 四、数据流设计

### 4.1 复习流程数据流

```
用户点击「开始复习」
        │
        ▼
useReviewQueue.ts
  → 查询 IndexedDB：due_date <= now()
  → 按 FSRS 优先级排序
  → 返回今日复习队列 Card[]
        │
        ▼
Review.tsx 渲染第一张卡正面
        │
用户点击「翻转」
        │
        ▼
显示背面内容
        │
用户点击打分按钮（1-4）
        │
        ▼
fsrs.ts: repeat(card, rating, now)
  → 计算新的 stability, difficulty, due_date
  → 返回新 CardState
        │
        ▼
db.cards.update(cardId, newState)  ← IndexedDB 写入
db.reviewLogs.add(logEntry)        ← 记录复习日志
        │
        ▼
下一张卡片 or 完成页
```

### 4.2 状态管理分层

```
Zustand（内存状态）
  - 当前复习会话（currentSession）
  - UI 状态（sidebarOpen, theme）
  - 今日统计缓存

Dexie IndexedDB（持久状态）
  - 所有卡片数据
  - 所有牌组数据
  - 所有复习日志

React 组件本地 state
  - 卡片是否已翻转（isFlipped）
  - 表单输入内容
```

**原则**：业务数据只存 IndexedDB，UI 状态放 Zustand，组件 state 只管 UI 细节。

## 五、离线 & PWA 方案

### 5.1 Service Worker 策略

使用 `vite-plugin-pwa` 自动生成 Service Worker，采用 **Cache First** 策略：

```
请求资源
  ├── 缓存中有 → 直接返回缓存（离线可用）
  └── 缓存中无 → 网络请求 → 存入缓存 → 返回
```

所有静态资源（HTML, JS, CSS, 图标）在首次加载时全部预缓存。

### 5.2 IndexedDB 容量管理

图片卡片上传时：
- 自动压缩到最大 1MB / 张（Canvas API 压缩）
- 整体 DB 超过 500MB 时提示用户清理

## 七、性能设计

### 7.1 大数据量场景（1万张卡片）

**问题**：一次查出所有卡片会导致内存爆炸。

**方案**：
- IndexedDB 查询带索引：`due_date` 字段建立索引，每次只取今日到期的卡片
- 卡片列表分页：每页 50 条，滚动加载
- 统计计算用 Dexie 的 `count()` + `where()` 链式查询，不全量读取

```typescript
// 高效查询：只取今日到期
const dueCards = await db.cards
  .where('due_date')
  .belowOrEqual(Date.now())
  .and(card => card.deck_id === deckId)
  .toArray()
```

### 7.2 翻卡动画性能

翻卡用 CSS 3D Transform（不用 JS 动画库），GPU 加速：

```css
.card-inner {
  transform-style: preserve-3d;
  transition: transform 0.4s cubic-bezier(0.4, 0, 0.2, 1);
}
.card-inner.flipped {
  transform: rotateY(180deg);
}
```

Framer Motion 只用于页面级过渡，不用于高频翻卡操作。

### 7.3 代码分割

路由级懒加载，首屏只加载 Home + Review 相关代码：

```typescript
const Stats = lazy(() => import('./pages/Stats'))
const Settings = lazy(() => import('./pages/Settings'))
const CardEditor = lazy(() => import('./pages/CardEditor'))
```

## 八、错误处理

### 8.1 IndexedDB 写入失败

```typescript
try {
  await db.cards.update(id, newState)
} catch (e) {
  // 写入失败：暂存到内存队列，页面关闭前重试
  pendingWrites.push({ id, newState })
  toast.error('保存失败，将在下次打开时重试')
}
```

### 8.2 IndexedDB 不可用（私有模式）

部分浏览器在无痕模式下限制 IndexedDB 容量（Safari）。
检测到后降级到 `localStorage`（仅存少量卡片，提示用户）。

## 九、后端架构（V2.0 预留）

V2.0 启用云端同步时，后端方案：

```
Fastify (Node.js)
  ├── POST /auth/login
  ├── GET  /sync/pull   → 返回服务端最新数据
  ├── POST /sync/push   → 接收客户端变更
  └── ...
SQLite（单文件，easy to backup）
  ├── users
  ├── decks
  ├── cards
  └── review_logs

同步策略：CRDT-like，以 updated_at 时间戳为基础
冲突解决：服务端为主，客户端本地变更优先级更高（离线写入优先）
```
