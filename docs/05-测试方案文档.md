## 一、测试策略

### 1.1 测试分层

```
E2E 测试（Playwright）          ← 关键用户流程，少而精
    ↑
组件测试（Vitest + Testing Library） ← 核心交互组件
    ↑
单元测试（Vitest）              ← 算法、工具函数，必须全覆盖
```

越往下越多、越快、越稳定。E2E 只覆盖核心主路径，不做穷举。

### 1.2 测试工具

| 工具 | 用途 |
|-----|------|
| Vitest | 单元测试 + 组件测试（Vite 原生，快） |
| @testing-library/react | React 组件行为测试（不测实现，测交互） |
| Playwright | E2E 全流程测试 + 截图验证 |
| fake-indexeddb | IndexedDB 内存模拟（单元测试用） |
| msw | 网络请求 mock（V2 后端对接时用） |

### 2.1 FSRS-5 算法测试（最高优先级）

文件：`src/algorithm/__tests__/fsrs.test.ts`

这是整个 App 的核心，算法正确性直接影响用户学习效果，必须全面覆盖。

```typescript
describe('FSRS-5 核心算法', () => {

  describe('新卡初始状态', () => {
    test('新卡 due 应设为当前时间', () => {
      const card = createNewCard()
      expect(card.state).toBe(CardState.New)
      expect(card.reps).toBe(0)
      expect(card.lapses).toBe(0)
    })
  })

  describe('第一次复习', () => {
    test('Again(1) 后状态应为 Learning，间隔 < 1天', () => {
      const card = createNewCard()
      const result = applyRating(card, Rating.Again, new Date())
      expect(result.state).toBe(CardState.Learning)
      expect(result.scheduled_days).toBe(0)  // 当天再复习
    })

    test('Good(3) 后状态应为 Learning，间隔约1天', () => {
      const card = createNewCard()
      const result = applyRating(card, Rating.Good, new Date())
      expect(result.state).toBe(CardState.Learning)
      expect(result.scheduled_days).toBeGreaterThanOrEqual(1)
    })

    test('Easy(4) 后状态应跳转到 Review', () => {
      const card = createNewCard()
      const result = applyRating(card, Rating.Easy, new Date())
      expect(result.state).toBe(CardState.Review)
      expect(result.scheduled_days).toBeGreaterThan(3)
    })
  })

  describe('稳定卡片复习', () => {
    test('连续 Good 评分应逐步增大间隔', () => {
      let card = createNewCard()
      const intervals: number[] = []
      for (let i = 0; i < 5; i++) {
        card = applyRating(card, Rating.Good, new Date())
        intervals.push(card.scheduled_days)
      }
      // 每次间隔应递增
      for (let i = 1; i < intervals.length; i++) {
        expect(intervals[i]).toBeGreaterThanOrEqual(intervals[i-1])
      }
    })

    test('Again(遗忘) 后 lapses 应 +1', () => {
      let card = createNewCard()
      card = applyRating(card, Rating.Good, new Date())
      card = applyRating(card, Rating.Good, new Date())
      const before = card.lapses
      card = applyRating(card, Rating.Again, new Date())
      expect(card.lapses).toBe(before + 1)
    })

    test('Again(遗忘) 后状态应变为 Relearning', () => {
      let card = createReviewCard()  // 构造一张已在 Review 状态的卡
      card = applyRating(card, Rating.Again, new Date())
      expect(card.state).toBe(CardState.Relearning)
    })
  })

  describe('due 时间计算', () => {
    test('due 时间应为当前时间 + scheduled_days', () => {
      const now = new Date('2026-01-01T00:00:00Z')
      const card = createNewCard()
      const result = applyRating(card, Rating.Good, now)
      const expectedDue = now.getTime() + result.scheduled_days * 86400 * 1000
      // 允许 1 分钟误差
      expect(Math.abs(result.due - expectedDue)).toBeLessThan(60000)
    })
  })

})
```

import 'fake-indexeddb/auto'
import { db } from '../../db'

describe('复习队列查询', () => {

  beforeEach(async () => {
    // 每个测试前清空数据库
    await db.cards.clear()
    await db.decks.clear()
  })

  test('只返回到期的卡片，不返回未到期的', async () => {
    const deckId = 'deck-1'
    const past = Date.now() - 1000    // 1秒前，已到期
    const future = Date.now() + 86400000  // 明天，未到期

    await db.cards.bulkAdd([
      makeCard({ id: 'c1', deck_id: deckId, due: past }),
      makeCard({ id: 'c2', deck_id: deckId, due: future }),
    ])

    const due = await getDueCards(deckId, 100)
    expect(due).toHaveLength(1)
    expect(due[0].id).toBe('c1')
  })

  test('暂停的卡片不出现在复习队列', async () => {
    await db.cards.add(
      makeCard({ id: 'c1', deck_id: 'deck-1', due: Date.now() - 1, is_suspended: true })
    )
    const due = await getDueCards('deck-1', 100)
    expect(due).toHaveLength(0)
  })

  test('超过 limit 数量时只返回 limit 条', async () => {
    const cards = Array.from({ length: 20 }, (_, i) =>
      makeCard({ id: `c${i}`, deck_id: 'deck-1', due: Date.now() - 1 })
    )
    await db.cards.bulkAdd(cards)
    const due = await getDueCards('deck-1', 10)
    expect(due).toHaveLength(10)
  })

})

  })

  })

  test('空行被跳过', () => {
    const csv = `front,back\nephemeral,短暂的\n\n\nword,词`
    const result = parseCSV(csv)
    expect(result).toHaveLength(2)
  })

  test('front 内容重复时检测并标记', () => {
    const csv = `front,back\nephemeral,短暂的\nephemeral,另一个意思`

## 六、边界条件测试清单

这些是容易遗漏的 bug 来源，必须逐一验证：

### 算法边界
- [ ] 新卡第一次 Again 后，间隔是否合理（不应变成负数）
- [ ] stability 值是否始终 > 0
- [ ] 连续 Again 100次，due 是否仍然合理
- [ ] 时钟跨天时（23:59 → 00:00），到期判断是否正确

### 数据边界
- [ ] 卡片正面内容为空时无法保存
- [ ] 卡片内容超长（10000字）时正常截断显示
- [ ] 牌组名称含特殊字符（emoji、< > & "）时正常存储和显示
- [ ] IndexedDB 写入失败时（磁盘满），不丢失当前复习进度
- [ ] CSV 导入文件为空时给出明确提示
- [ ] CSV 导入含 BOM 头的文件时正常解析

### UI 边界
- [ ] 牌组卡片名称很长时省略号处理，不撑破布局
- [ ] 复习队列为 0 时不显示「开始复习」按钮（或 disable）
- [ ] 快速连续点击翻转按钮不产生动画错乱
- [ ] 快速连续点击评分按钮不重复写入日志

### 移动端边界
- [ ] 横屏模式下布局不破碎
- [ ] 虚拟键盘弹出时卡片不被遮挡
- [ ] 低端设备（2GB RAM）下动画是否自动降级

  test:
    steps:
      - name: 单元测试 + 覆盖率
        run: pnpm vitest run --coverage

      - name: 覆盖率检查（低于阈值则失败）
        run: pnpm vitest run --coverage --reporter=text --threshold=80

      - name: E2E 测试
